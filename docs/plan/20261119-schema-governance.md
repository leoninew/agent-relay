## 技术设计

| 项目 | 拟定契约 |
| --- | --- |
| 标识 | 房间、频道（含默认频道）、成员（含固定人类成员）、话题、消息、投递、角色模板、查阅请求使用 `tsidpy` 规范字符串，校验 13 字符、规范字母表和 64 位范围。数据库和 API 只持有规范大写文本，不接受旧 ID 作别名。种子用固定的合法 TSID。关联表保留自然复合键，原频道作用域主外键和业务唯一约束也保留。 |
| 语义标识 | 默认频道按 `is_default`、人类成员按 `kind='human'` 在各自作用域找真实 ID；数据库保证至多一个，房间/频道创建事务保证应有的记录存在。调用者使用发现出的 ID，移除旧常量和 SQL 默认 ID，不改变无频道参数的接口约束。 |
| 生成与恢复 | T02 集中维护 `tsidpy` 生成与验证。Web 和 CLI 不各自随机选 node；建议在同一房间作用域先向服务端领号，不创建业务记录，再携带该 ID 提交一次创建。结果不明时按同一 ID 查询。T02 冻结路径、DTO 和错误语义；运行多个生成实例前须协调不同 node，未配置时只支持单一活跃发号实例。现有唯一约束仍是防线，不把碰撞误认为请求重放。 |
| 审计 | 业务表（不含 `alembic_version` 等系统表）共用 UTC 时间格式和 INSERT `DEFAULT`，可提供真实创建时间；`updated_at` 由仓储写入，覆盖 ORM flush、批量更新和 upsert，软删同事务更新。保留投递与查阅位置已有时间初始化和消费合同；业务时间字段不改作通用审计列。 |
| 时间展示 | 存储层保存 UTC，API/MCP 和 CLI JSON 保留可机器解析的 UTC 时间。Web 沿用浏览器本地时区渲染；CLI 仅在已有面向人的文本时间字段里转运行机器的本地时区，不新增时间列或输出模式。旧库带显式非零偏移的已知时间迁为等价 UTC，不改变时刻，不猜测不明确的历史时区。 |
| 软删与归档 | 软删表保存 `is_deleted`、`deleted_at`；按 #645，状态与时间由业务写入在同一事务内维护，不使用跨列 `CHECK`。保留布尔取值、活动筛选和部分唯一索引。频道保留 `status`、`archived_at` 表达归档；旧 `status='archived'` 且有归档时间的记录保持归档，旧活动状态但带删除标记的记录转换为软删，非预期组合报告并退出。投递状态及历史查询按原业务定义保留。 |
| 基线 | 就地更新 SQL-first DDL、种子及 ORM，使用新的 revision 识别新布局。新程序可初始化空库、打开新库；遇到旧 revision 必须在任何 Schema 修改前失败并提示独立脚本。不以原 revision 或 `stamp` 假装迁移完成。 |
| 迁移边界 | 停机后从只读的一致性 SQLite 副本和备份图片向新目标写入；按原作用域维护旧→新映射，重挂 PK/FK、自引用、事件引用和受管图片链接。保留业务时间、`seq`、`event_id` 及其高水位、依赖 `rowid` 的相对顺序、`publication_id`、Codex 会话和回执。Git 工作目录及分支保留已保存值。无可证的历史创建时间统一回填并报告；不修改普通正文和外部链接。 |
| 消息发布 | 成功响应后清理对应发布缓存和未改动的草稿，异步期间编辑过的草稿保留。发送失败时提示并保留草稿，不查询发布结果、不自动重发、不增加确认控件，由用户决定清理或再次发送。消息发布与后台 Codex 投递分别处理。 |
