## 技术设计

| 项目 | 契约 |
| --- | --- |
| 模板资源 | `MemberRole`：`id`（服务端生成、编辑不变）、`name`、`prompt`；全站共享，不挂在房间或频道下。列表按名称、ID 稳定排序；返回完整正文供编辑，表格仅展示摘要。 |
| 角色 API | `GET /api/member-role` 返回数组，`POST /api/member-role` 按 `{name, prompt}` 创建并返回对象（201）；`PATCH /api/member-role/{role_id}` 接收相同字段并返回保存后的对象（200）；`DELETE /api/member-role/{role_id}` 返回 204。沿用现有响应和错误格式，不新增权限体系。 |
| 数据校验 | 名称去除首尾空白，1–80 个字符，规范化后区分大小写唯一；重复返回 409、`member_role_name_conflict`。提示词按普通消息正文规则校验，去除首尾空白后 1–6000 个字符，保留内部换行，首版不配置能力引用；因此不能包含需要显式技能引用的 Markdown 链接。不存在的角色返回 404、`member_role_not_found`。 |
| 添加成员 API | `POST /api/room/{room_id}/channel/{channel_id}/member` 增加非必填的标量 `roleId`；缺省或 `null` 不发消息，不接收数组或客户端提交的提示词。201 响应保留现有 `CreatedMember`，不加角色绑定、消息 ID 或提示词投递状态。 |
| 消息与事务 | 复用普通发布规则：固定用户为发送者，`mentionedMemberIds` 仅含新成员，`topicIds` 为空，正文取保存时的模板值。成员、消息及其原有事件和待投递记录一起提交。消息发布走同一请求事务，不在成员事务内调用 Codex 写操作，不改变后台派发。 |
| 前端导航 | 将目前重定向的 `/settings` 接到独立设置页；齿轮保留语言和关于入口并增加「角色与提示词」。从频道进入时记录当前频道路由，返回原频道；直接打开设置页时返回聊天首页。 |
| 并发和历史 | 目录加载失败不拦截无角色提交。角色在打开表单后修改，提交时取数据库当前版本；角色被删除，整次添加不落库并沿用表单错误显示。角色与历史消息无引用关系，编辑、删除不改历史。 |
