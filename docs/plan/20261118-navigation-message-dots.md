# 计划：聊天室与频道的新消息提醒
最后修改时间: 2026-11-18 17:25:05

审查状态：Accepted。依据同名意图及用户「记录后实施」授权。

## 实施顺序与设计
1. 扩展只读查询、DTO 与 HTTP 路由，一次读取所有有效房间与频道的最新非本人、未删除消息序号；空频道返回 0。无需拉取正文、推算数量或改变消息投递。
2. 应用级单一轮询：前台约五秒一次，恢复可见时立即刷新，失败保留最后成功快照。浏览器本地按房间、频道保存查看位置；首次成功摘要作为基线，后续新建频道从 0 开始。
3. 从已成功展示的当前时间线推进位置。顶部 RoomSwitcher、侧栏 ChannelBar（含默认频道）仅消费派生状态；圆点紧随可截断名称，附无障碍说明。
4. 后端查询用例覆盖空频道、本人、删除、归档和房间隔离；前端验证首次、刷新、前后台、失败及按频道清除，运行类型、格式和现有测试。

## 约束与回滚
子任务协调不适用。查看位置仅代表本浏览器，轮询有短暂延迟。保持当前频道事件订阅不变。回滚可撤除导航消费、轮询与独立只读接口，不需恢复数据。

## 实施记录与开发检查
工作区已实现 `GET /api/room/channel-message-heads`、应用级轮询、本地查看位置及两处导航圆点。为避免过滤掉的消息被代为清除，仅在未筛选的时间线成功展示后推进到该页实际展示的最大序号；查看历史页不会越过当页。无数据库迁移，未改投递、WebSocket 或查阅回执。
