# Agent Relay 统一术语
最后修改时间: 2026-11-07 19:41:39

## 状态与适用范围

Accepted。2026-11-07 用户接受统一术语建议。界面、错误文案、设计、计划和后续实现采用本文；第三方协议名和真实证据字段保留原名。相关业务规则见[总体设计](codex-session-chat-collaboration.md)与[后端计划](../plan/20261107-backend-from-web.md)。

## 概念与命名

| 英文 | 统一中文 | 含义与命名边界 |
| --- | --- | --- |
| Room | 聊天室 | 项目的协作空间，包含成员、话题和消息；上下文明确时可简称房间。代码使用 Room/roomId |
| Topic | 话题 | 聊天室内可订阅的消息分类和路由目标，一条消息可关联多个话题。代码使用 Topic/topicId/topicIds |
| Member | 成员 | 聊天室中的协作身份，持有名称、话题订阅和会话绑定。代码使用 Member/memberId |
| Session | 会话 | Relay 对模型持续交互上下文的通用抽象。代码使用 Session/sessionId |
| Codex Thread | Codex 会话 | Codex 持久保存对话历史和上下文的对象，是当前 Session 的底层实现。协议保持 thread/start、thread/resume、threadId |
| Turn | 轮次 | 会话中的一轮模型执行，保留 turnId；不承诺一条聊天室消息独占一个轮次 |
| Message | 消息 | Relay 持久接收并在聊天室中呈现的发布内容，携带明确路由目标 |
| Delivery | 投递记录 | 一条消息向一个实际接收成员的分发事实；成功边界是目标队列确认入队 |
| Subscription | 订阅 | 成员与话题的关系；统一写“订阅话题”“话题订阅”，相关动作写“订阅/取消订阅” |
| OS / runtime thread | 线程 | 程序并发执行的技术概念，不能用来称呼成员的模型会话 |

## 用词约束

- Topic 的中文统一使用“话题”，不再交替使用“主题”；“主题”可用于界面配色主题等其他概念。
- 当前没有独立 Channel 实体，不引入“频道”作为话题或聊天室的别名。消息属于聊天室，可关联多个话题，直接 @ 消息也可没有话题。
- Session 和 Codex Thread 是抽象与底层实现的关系，不是两份独立对话历史。映射由会话绑定记录维护；不因中文统一而更改 Codex 协议名或当前 HTTP 的 sessionId。
- 产品叙述写“发现会话、选择会话、添加成员、绑定会话”。添加成员不等于创建会话；Codex 技术字段保持真实 threadId，Session/sessionId 对应被选择的原会话。
- 如果以后引入围绕某条消息展开的一组回复，称为“讨论串”，另行定义。本次没有增加该实体；replyToMessageId 仍只是消息引用关系。

统一表述：**成员绑定会话，成员订阅话题；消息发布到话题或 @ 成员，Relay 合并目标、排除发布成员并校验非空，再向实际接收成员绑定的会话入队。**
