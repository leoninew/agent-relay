## 仍适用的技术事实

- 本机 Codex 0.167.0 已验证独立 app-server 创建持久会话、queue 入队、忙碌时继续入队，以及显式发布工具通路。采用 Relay 管理持久会话的既有决定保留。
- queue 的成功回执仅表示入队，不表示接收者已读、已执行或已回复。相同 clientUserMessageId 重复提交会形成不同队列项，因此不能因无回复或超时自动重发。
- 话题和 @ 取并集、去重、排除发布成员，全部目标有效且实际接收人非空，才持久保存消息及投递。引用不补造目标。
- 成员只有携带明确话题或 @ 的发布进入聊天室；普通执行输出、turnId 和 final_answer 不决定路由，不主动读取这些内容来构造房间消息。

已有[协议能力证据](evidence/20261107-codex-0.167.0.json)继续保留。[队列恢复探测](evidence/20261107-codex-queue-recovery.json)只作为已发生的调查记录，不产生本轮备份/恢复任务或额外前置。

## 当前实施关注点

1. 一次发布原子保存消息、显式目标、实际投递和发布标识，避免重复落库及半条记录。
2. 向实际接收成员的 Codex queue 提交本次消息，保存匹配的回执；结果不明就如实记录 unknown，不自动重新提交。
3. Web 和 CLI 查询同一份持久记录，页面状态、数量和秒级时间对应已有事实；不虚构接收、已读或回复状态。
