### N6：成员/话题请求与事务、零个或多个订阅

总计划修订 21 近期方案及 D04 已实现并局部接受；N5 已接受产物继续有效。

按一次业务操作组织请求、事务和响应：添加成员一次提交 sessionId/name/topicIds；外部 Codex 只读核验在事务外，随后短写事务复核资源并原子保存 Session/Member/订阅。编辑成员原子更新名称和订阅；话题创建/编辑各自提交，删除话题与订阅清理同事务。成功响应返回页面需要的保存结果及受影响资源，复用现有资源模型、按实际影响补齐；前端无需额外 GET 成功才确认保存。内联话题仍是独立创建，不强行合并为成员加临时话题的组合事务。

要解决的实际问题：删除最后一个话题会让成员没有订阅，但该成员随后连改名都无法保存；新聊天室没有话题时，也不能先加入一个仅通过 @ 协作的成员。

已接受“成员可以订阅零个或多个话题”。后端 CreateMember/UpdateMember 继续要求 topicIds 字段，但允许显式空数组；名称、会话绑定、目录和加入可用性检查不变。取消订阅全部话题或删除最后话题不删除成员、不修改原会话；旧消息/Delivery 按既有发布快照保留，新的话题消息按当前订阅路由，直接 @ 始终按活动成员身份路由。

实施顺序：先调整请求模型并核对现有保存/查阅/位置规则，再向 T09/T10 交付空数组契约。Web 去掉订阅必填标记和阻止空订阅保存的校验；CLI 加入/编辑可不传 --topic-id，明确发送 topicIds=[]。创建和独立编辑弹窗继续分开，不在编辑时刷新候选会话。

完成效果：无话题也能加入可用成员，随后直接 @；删除最后一个订阅话题后仍能改名、保存和被 @。发消息仍须指定话题或 @，并至少产生一个实际接收人；零订阅不等于允许无接收人的消息。

修改限于相关资源用例/响应、请求模型、相应表单/CLI 和正常业务检查；现有 member_topics 已允许空关系，无需为此新增迁移。R03 已在本轮单独完成，见上节。D05 内联话题独立提交继续沿用。

## Technical decisions / 局部技术设计

- N5：历史分页与 loaded/list 合并，已加载会话重新 read；idle/active 且未归档才 usable，忙碌允许加入。不可用返回 unavailableReason，未接入不能判定宿主已死；当前不适配独立实例。加入前重新核验身份、目录和 usable。
- 刷新候选或手动刷新聊天室时，将活动成员/原会话的 presence、activitySource、observedAt 等观察字段在短事务保存；不覆盖名称/订阅。普通事件和元数据读取不发起外部 RPC；刷新失败返回错误，保留上次观察和时间。
- N6 按已接受 D04 允许 topicIds=[]：成员身份/会话绑定与订阅分开；创建和编辑按同一契约处理，发布处继续校验实际接收人非空。
- 删除语义建议只改变后续新路由。节点 deletedAt 与订阅清理原子保存；不删除/重算既有 Message 或 Delivery。重新加入生成新 memberId；原成员留存用于历史，不增加会话重绑定或绑定版本机制。
- R03 已实现：Store/Queries 按 roomId 定向访问，创建/编辑/删除不装载消息及全部房间对象图；HTTP 写事务由 request 切面提交，外部核验前的短读及时结束。时间线沿用 T08 有界查询。
- 查询与用例明确区分活动节点校验和历史元数据解析，集中提供活动条件；历史 DTO 继续保留已删除节点供旧消息解析，新的目标校验只接受活动节点。
- activity/activitySource/observedAt 表示最后一次真实元数据观察；普通资源读取不更新 observedAt，不用读库时间伪装 Codex 新观察。投递成功独立由 Delivery 表达。
- 根目录 migrations/sqlite 管理 Alembic revision 及同级 sql/ 文件；alembic.ini 位于根目录。显式 migrate 入口 upgrade head，Make/容器启动先迁移；存储只检查版本并管理资源事务。无旧结构探测、自动 stamp 或旧库接入参数。
- 用户取消角色字段；成员只编辑名称和订阅，会话原绑定不变。会话选择项移除模型提供方显示，驱动仍使用真实 provider 做元数据核验。迁移中的 SQL 清除成员 payload.role；不为已移除字段或旧协议新增反向测试。

- 使用共享 daemon 的 app-server proxy，WebSocket 帧经 stdio 转发；请求范围连接结束只关闭自身 proxy。没有独立执行宿主、启动自动 resume 或运行时锁。
- 默认 codex 命令支持 Windows 官方 npm 安装：定位同一安装的 node_modules/@openai/codex/bin/codex.js，使用相邻 node.exe 或 PATH 的 Node 直接启动，不解释 shell 包装脚本或回退到其他 Codex 安装。连接结束关闭标准输入，让 proxy 和 Node 正常退出，超时只结束自身子进程。
- thread/list 遍历全部分页，显式全部公开 sourceKinds、modelProviders=[]、archived=false/true、useStateDbOnly=true。按房间规范路径匹配返回元数据，不因上游精确 cwd 字符串漏掉 Windows 等价路径；不扩展符号链接或子目录。
- GET session 返回名称、原会话 ID、provider、presence、observedAt、archived、memberId；已加入与归档标明，不自动变更归档或按忙闲隐藏。
- POST member 仅接受 sessionId/name/topicIds。先校验资源，事务外 thread/read(includeTurns=false) 核验原 ID/cwd/provider，再写事务复核名称/会话唯一性和订阅，原子保存 Session/Member，返回 201。外部错误 503、重复 409、跨目录/订阅无效 422；失败不部分落库。
- 直接移除 operationId 创建协议、创建状态 UI、后台创建、身份注入与会话重命名。SQLite schema 3 删除废弃创建操作和托管索引/列，保留资源、已绑定成员和消息；没有旧业务接口兼容。
- 前端恢复 Reka 单选和清空、刷新、加载/错误/空态、重复禁选；字段级必选校验与其他表单错误独立，刷新失效选择清空。编辑名称只改成员业务字段。
