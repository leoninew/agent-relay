## Technical decisions / 局部技术设计

- 本次显式发布所需字段为 content、topicIds、mentionedMemberIds 和可选 replyToMessageId；身份与来源由真实调用上下文取得。接口参数/返回随本功能定义，不要求事先冻结未来所有工具。
- D07 当前要求为已有会话可用的明确发布入口，模型只填内容/目标/可选引用；服务从受控调用上下文解析持久成员绑定，先提交发布事务再返回结果。具体入口（例如 MCP/CLI）和身份、来源调用键须在本节点 Plan 核验后接受，不依赖重新创建会话或给任意已有 thread 注入 dynamicTools。
- room/member/session 由受控调用上下文绑定并核验，不能接受请求正文自报的 sender。身份注册、失效和重连按 T01 契约处理。
- 来源幂等键按实际入口可稳定提供的调用身份设计，归入房间/成员发布域；不能预设任意入口都有 turnId/callId。重放返回原消息和实际目标，不做正文语义去重，不依赖进程代际或临时 RPC request id。
- 恢复已落库但响应丢失的调用时查原来源键；宿主是否重放未决工具请求尚未验证，不从历史中的未完成工具项擅自执行新写入。本机已有 Codex 会话入口属于本任务主线；额外宿主才归 T12。
- 身份、目标和引用按同一事务校验；成员答复的目标取本次字段，不从触发消息继承。引用歧义不填，不阻止有效显式目标发布。
- D03 已接受：在统一路由中排除可信发布成员，显式 @ 自己不覆盖该规则；排除后无实际接收人则工具报业务错误，不创建消息。自动链限制后置，不作为本次前提，不因自身排除暗加限额。工具回调和历史观察指向同一来源，不各生成一条消息。

## Implementation outline / 实施安排

1. 先在 Plan 核验并接受已有会话的入口、身份与来源键契约，再实现受控入口与成员身份解析，连接统一发布用例；定义工具错误和幂等返回。
2. 实现来源调用登记、重放和目标/引用校验；接上真实 Delivery 后台提交。
3. 按已确认规则排除发布成员，交付给成员的简短发布/查阅使用说明。
4. 验证 Web 可查询成员发言和投递，模型持续过程输出与无标记最终答复不进入时间线。

## Checks and risks / 检查与风险

- 无目标、正文伪 #/@、代码/引用标记、无效目标、跨房间引用和身份伪造全部拒绝或忽略相应非发布输出。
- 显式话题/仅 @/叠加三种成功；重复 sourceCallId 只一条消息；来源和入队关联不明确不猜引用；自身排除有对应测试。
- 发送者命中话题或被显式 @ 均不会向自己投递；只剩自己则返回业务错误且无持久发布结果，其他无效目标不能被排除步骤掩盖。
- 跑入口/发布/驱动集成 pytest、mypy、ruff；真实链路用隔离会话。若入口能力与 T01 不符，回到 Plan 修订，不用正文解析兜底。
