### N6：单次入队失败有状态，不阻塞其他业务

主要结果是本次投递失败后能查到状态和原因，其他目标及后续消息仍能继续处理。现有实现已有 rejected/unknown，沿用并检查记录、查询和展示，不另建失败状态体系。

1. 明确拒绝记录 rejected；无法确认结果记录 unknown；保存可读原因，供现有查询和 T09 展示。一次失败结束本次提交，不因等待、超时或无回复重新入队。
2. 将单条处理异常限制在本次工作范围，避免 future.result 抛错直接退出整个后台循环；释放本次本地占用，让其他目标和后续消息继续处理。发布请求仍以本地持久保存为完成点，不等待外部投递。
3. 保留已实现的原输入接收核验、原目标快照和新提交后的 FIFO 首项一次启动，不扩大消费或恢复行为。未确认的事实保持原状态，不把日志或暂缺证据当成成功。

用户可见效果：失败显示在对应投递记录上，聊天室仍可管理资源、发送和处理后续消息。本期不新增后台运行状态机、运行诊断接口、公平调度改造或 unknown 原队列持续核对；修订 20 的相关建议撤出必做。

主要结果是用户携带话题或 @ 发送后，绑定的原会话实际收到；直接前置为 T01 已收敛的消费/接收契约、T02 的接入可用性产物，以及 T03 既有持久投递和真实发布者身份。

## Technical decisions / 局部技术设计

- N5 沿用总计划修订 19：仅新消息入队后检查当前 idle 和 FIFO 首项。首项的队列 ID、客户端标识均匹配真实 Relay 回执且未尝试时，先短事务记录 activationAttemptedAt，再按该项 ID 启动一次；不跳项、不自动 resume、不在启动时或观察循环中再次启动。用户中断后仍等待的项保留 queued 并说明在原 Codex 继续。
- 后台有界读取尚未确认的原会话输入，每轮最新页并逐步补查旧页，只匹配 userMessage.clientId。queued/unknown 匹配后保存 received、receivedAt（本地确认时间）、输入项 ID 与 turn ID；暂缺不推定失败或收到。queuedAt 与启动尝试事实单独保存；均落现有 payload，无新增迁移。
- 队列驱动返回可区分的 queued/明确 rejected/unknown 结果。成功必须核验本次客户端标识及队列项 ID；保存目标会话、原始凭证必要字段和本地确认时间。
- D02 最新纠偏为已有会话绑定。复用 T02 的共享 daemon proxy 协议与原绑定，实现 queue/add 与 queue/list；不创建替代会话，不以 resume 接管原宿主。T01 已证明 active 可入队、分页可用、相同 clientUserMessageId 会产生新队列项；核对不能重放 add。
- 调度定向查询并领取 DB pending，不装载全部消息对象图；同一真实 session 按持久顺序发起，控制总并发，不等上一条模型输出。调用前短事务写 submitting、稳定 clientMessageId 与领取版本，外部 I/O 不持锁。
- 按已保存 Delivery.targetSessionId 提交，当前成员删除/订阅变化不重算目标，不因活动成员过滤漏掉旧 pending；成员重新加入产生的新 ID 不接收旧投递记录的归属。
- 成功/拒绝/未知通过条件更新保存；事件随后续 T08 接入，过期执行者不能覆盖新事实。RPC 已可能发出后，取消、超时、响应不匹配均保留 unknown；历史暂缺不是拒绝。
- 已确认 queued 永不因输出等待转失败。重启遗留 submitting 进入 unknown 核对，不恢复成 pending；后台唤醒丢失通过持久扫描找回尚未提交工作。
- 不以忙碌或 notLoaded 代替实际入队结果。queue/list 准确命中只证明排队，列表暂缺不判拒绝；N5 用有界输入历史关联确认接收，不新增模型输出观察。
- Prompt 只含本次消息、必要成员/房间/消息标识、显式目标与可选查阅入口，不恢复已移除的角色/职责字段，不注入 Offset 区间全文。明确拒绝后的人工再发需新操作记录；不实现自动重试引擎。
