## Technical decisions / 局部技术设计

- 浏览状态和草稿路由分离：去掉 selectedTopicId 作为 Composer 默认目标的隐式联动。常规话题/成员点击、刷新和引用定位只改变浏览；空正文、已有正文和切换筛选结果一致。显式“引用回复”仍按既有要求复制活动话题/@ 到草稿，不由服务端补造目标。
- 后续状态管理改进：房间有唯一可写状态，继续使用现有 Pinia 管理；统一保存 topics/members/sessions/messages，RoomPage 不再与 catalogs 共享数组再分支双写。资源响应和整份刷新通过统一入口更新；删除话题后明确重新读取该房间，订阅不另建一份前端权威。
- N6 按已接受 D04 统一订阅可选标记和校验；成员仍须有名称及真实 sessionId。删除最后话题后的成员可正常编辑，仅 @ 路由不依赖订阅。
- N5 观察展示：Member DTO 承接 activitySource/observedAt，左侧成员状态紧随名称，不显示观察时间，未知时显示原因。点击“刷新聊天室”先请求真实会话核验，再 loadRoom；普通事件/元数据查询仍只读 Relay，不把观察时间当接收承诺。
- Delivery 使用 pending/submitting/queued/received/rejected/unknown；详情展示真实入队与接收凭证，时间下方换行，消息和全局统计同步。只显示目标 userMessage 的接收事实，不展示助手输出。
- queued 文案为“已入队”，received 为“已进入会话”；其余依次为“待提交/提交中/已拒绝/结果未知”。received 的状态时间是本地确认时间，不表示模型理解；另展示 queuedAt，以区分两个事实。不将旧 delivered 转成真实凭证。
- @ 区仅放明确 mentionedMemberIds，有则展示、无则隐藏；实际收件成员在分发详情，复用 MemberIdentity/头像颜色，无 taglist 背景、不用顿号拼接，不新增接收人预览或“直接点名”区块。
- 右上选择器显示已选房间名称；左上不重复名称或路径。消息时间有秒，状态时间在状态下换行、有值才显示，不放 tip；复用统一格式和 Typography 层级。
- 人工引用带原话题与直接 @ 到草稿并保留已有正文；引用定位按单条读取，跨页/筛选可跳转。发送仍取当次结构化目标，服务为最终校验者。
- publicationId 在一次发布意图内稳定；失去响应先找回。已发布但刷新失败分开反馈，不恢复成未发送并鼓励重复提交。
- 统一 AppLoading/AppSpinner/AppButton/Reka Toast；字段错误在字段附近。事件重复去重、断线补取、房间切换取消旧请求；资源事件或明确刷新使房间与目录缓存失效。
- 查阅位置及位置后数量不叫精确未读；成员状态注明来源/新鲜度，忙碌不禁用正常路由或暗示无法入队。
- D02 最新纠偏：添加成员先加载房间目录的真实会话，单选后提交 sessionId/name/topicIds，返回真实成员；已加入禁选、加载/空态/错误/刷新和字段校验同步。成员创建操作及 operationId 状态移除。
- 重启读取原绑定，不自动 resume 或创建替代会话。成员观察时间与投递结果分别展示，busy/notLoaded 不等于无法入队；额外宿主仍归 T12。
