# Intent / 意图：频道归档
最后修改时间: 2026-11-17 14:59:37

## Review status / 审查状态

Accepted

## Background / 背景

频道已支持排序和删除。现有删除通过 `archived_at` 标记，并清理成员和待投递项；用户要求独立的轻量归档，只切换状态，减少房间频道列表中的干扰。

## Goals / 目标

- 频道增加 `active` / `archived` 状态枚举，既有频道默认为 `active`。
- 房间频道列表默认不查询、不展示归档频道。
- 非默认、非当前频道在 hover 时展示“归档”文字，点击后通过确认框执行。
- 归档保留频道内容、成员、投递和工作目录。
- 归档时填写 `archived_at`，切换项目时重新拉取频道列表。

## Non-goals / 非目标

- 不增加恢复归档、归档管理页或批量归档。
- 不改变已有删除、消息投递或 worktree 清理语义。
- 不替用户暂存或提交本次变更。
- 不编写或运行数据迁移单元测试。

## User stories / scenarios / 用户故事 / 场景

- 用户在当前频道工作时，将其他暂时不用的普通频道归档；当前频道和默认频道没有归档入口。
- 用户取消确认时列表不变；确认成功后目标频道隐藏，当前频道和其他频道的相对顺序不变。
- 请求失败时保留目标频道，确认框显示错误并允许重试。

## Acceptance criteria / 验收标准

- A01：模型、数据库和 API 返回合法状态；旧数据库增量升级后原频道均为 `active`。
- A02：归档更新频道状态并填写 UTC 归档时间，保留成员、消息、投递和目录；重复归档保留首次归档时间，旧的归档记录缺少时间时在再次归档时补写。
- A03：服务端默认列表和前端可选列表均排除归档频道，按 ID 查询仍保留历史资源。
- A04：仅非默认、非当前且有效的频道拥有归档文字入口；键盘聚焦时也可访问。
- A05：确认前不发送归档请求；取消不改变频道；确认时再次检查目标资格；成功隐藏、失败保留。
- A06：服务端拒绝默认频道归档；CLI/MCP 的既有 `channel_archive` 操作使用新的状态归档接口。
- A07：切换项目时重新请求该项目的频道列表；新增或已归档频道及时反映到列表，失效的最近选择按既有规则回退默认频道。

## Workload assessment / 工作量评估

工作量中等，覆盖一次增量迁移、频道应用/持久化接口、前端列表和确认框，以及相关回归检查。复杂度中等：现有删除标记与新增状态必须区分，当前频道属于浏览器本地选择，不能当作全局服务端状态。主要风险是误用删除入口或迁移影响既有数据；通过独立归档方法、业务校验、代码检查和应用及接口测试控制，不编写数据迁移单元测试。

结论：保持单任务。交付是同一条归档交互，接口、状态和确认行为紧密耦合，主会话串行实施比拆分共享频道文件更清晰。

## Candidate tasks and dependencies / 候选子任务与依赖

不适用，保持单任务。

## Open questions / 待定问题

暂无需要用户确认的未决事项。

## Decisions / 决策

- 新增独立状态；按用户最新反馈，归档同时写入 `archived_at`。既有“时间非空即删除”的资源可用性判断需结合状态区分归档与历史删除，避免影响历史读取、目录保留和现有投递。
- 进入项目时强制刷新频道，保留请求合并和本地选择；不让已加载缓存跳过项目切换所需的请求。
- 按用户补充，不新增 CHECK、外键等数据库约束；状态枚举和默认频道限制由业务代码校验。
- 按用户补充，不编写或运行数据迁移单元测试；保留必要的迁移实现，不恢复已删除的持久化测试目录。
- 当前频道以浏览器实际选中频道为准，在展示、打开确认和执行确认时检查；服务端保证默认频道不可归档。
- 复用现有 AppDialog、按钮和侧栏交互样式，提供明确的取消与确认操作。

## Risks / assumptions / 风险 / 假设

- 不同窗口可以有不同当前频道；本次不引入跨窗口全局当前频道锁。
- 归档不暂停既有投递任务，也不清理资源；填写归档时间后，既有活动频道名称唯一索引允许新建同名频道。
- 共享工作树存在已经暂存的路径改造，实施只改工作文件，不改暂存区。

# Intent / 意图：统一频道缓存键
最后修改时间: 2026-11-17 17:24:34

## Review status / 审查状态

Accepted

## Background / 背景

用户要求缓存键不再各自拼接，业务缓存统一为频道粒度，频道列表为房间粒度。现有快照、草稿、技能和浏览器存储使用不同前缀，页面实例还按组件类型复用，需要统一范围与组织形式。

## Goals and acceptance / 目标与验收

- 使用唯一键生成入口，频道范围为 `conflua:room:{roomId}:channel:{channelId}`，业务资源名接在范围之后；ID 分段编码，避免分隔符碰撞。
- 快照、草稿、技能、待确认发送、待确认频道创建和话题/成员排序按频道隔离；页面实例也按频道标识。
- 频道列表和该列表的导航偏好按房间保存；切回项目仍刷新频道。
- 项目列表不再通过已加载标记跳过查询；真正的全局偏好使用统一的 app 范围。
- 启动时转存并移除旧浏览器键，保留草稿、待确认发送/创建及已有排序，已存在新键时以新键为准。
- 项目删除成功后清理其所有频道缓存及房间导航状态，保留其他项目和全局偏好；重置后已失效的频道列表请求不能恢复缓存。

## Scope and decisions / 范围与决策

- 本次只改前端键、缓存范围和必要检查，不改数据库或后端配置缓存。
- 全局设置、面板偏好与项目排序是应用偏好；最近频道和频道列表顺序是房间导航状态，按各自所属范围组织，不复制成每个频道一份。
- 创建结果未知记录使用发起创建的当前频道作为范围，显式传入频道 ID；旧记录按该房间最近选择衔接。
- 保持单任务：键生成与调用方必须一起切换，串行实施避免混用。
