# Intent / 意图：忙碌成员打断
最后修改时间: 2026-11-15 22:06:11

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

- 左下角成员列表已有 Codex 忙碌状态，用户希望直接打断该成员当前执行的轮次。
- 沿用共享 daemon 的公开 `turn/interrupt(threadId, turnId)`，完成前端、HTTP 和适配层交互。
- 本机 CLI 与共享 daemon 均为 0.169.0；schema 和随机不存在会话的 RPC 探测已确认方法可达，尚未对工作会话执行中断。

## Non-goals / 非目标

- 不清空消息队列、不撤回已接收的输入、不回滚执行结果、不自动启动下一轮。
- 不新增执行宿主、终端按键模拟、数据库字段、CLI 或 MCP 打断入口。

## Scenarios / 场景

- 忙碌 Agent 行默认显示“忙碌”；鼠标悬浮时在原状态位置显示“打断”文字，选中成员不触发替换；键盘导航仅在打断按钮本身获得可见焦点时显示动作。提交期间防止同一目标重复操作。
- 状态过时且会话已空闲时，返回当前无运行轮次；目标已结束时不报告打断成功。
- 不可达、身份或目录不符、方法不支持、结果未知时提供明确反馈；切换房间或频道不污染新页面。

## Acceptance criteria / 验收标准

- A01：有效忙碌 Agent 在鼠标悬浮时于原状态位置隐藏“忙碌”并显示可访问的红色“打断”文字按钮；选中成员本身不触发替换。无背景或悬浮背景变化，切换不位移；操作不触发成员筛选或拖动，并防止重复提交；不追加图标或中间文案。
- A02：频道范围接口从有效成员绑定解析目标，复核会话身份、目录、可用状态并定位运行轮次，数据库读取范围在外部 RPC 前释放。
- A03：同步等待目标轮次中断结果，只提交一次；区分已确认中断、无运行轮次及明确拒绝或未知，不从空回执推断完成；界面不显示“打断中”等中间文案。
- A04：前端提供中英文提示、刷新真实成员状态，错误沿用 `code/error/requestId`；不清空队列或乐观设置空闲。
- A05：覆盖关键边界与必要开发检查，记录实际证据和未验证事项。

## Workload and decomposition / 工作量与拆分

中等工作量，覆盖一个端到端动作。主要风险为取消确认与异步页面状态；已有会话定位和错误处理可复用。同一会话完成，不建立独立 task；验收以父级意图、计划为准。

## Questions and decisions / 问题与决策

- 无未决需求问题。沿用上一轮已说明的当前轮次打断语义；等待队列保持原行为。
- 用户已明确“记录任务并实现”，授权建立前置记录并推进实现及必要开发检查；整体 Verification 按 SpecFlow 默认另行授权。

## Risks / assumptions / 风险 / 假设

- RPC 接受不等于最终中断；通过目标轮次历史进行有界同步确认，超时仍未确认时返回结果未知错误。
- 会话可能自然结束或开始新轮次；保留最初定位的 turnId，确认过程不改换打断目标。
- 宿主是否自动消费下一条尚未实测，本功能不控制该行为。
