## Technical decisions / 技术设计与决策

- 复用 MessageService 的请求事务，原子保存消息、接收人路由和 delivery；不增加消息入库文件锁。后台只处理已提交任务，发布响应不等待 Codex 提交。
- 复用 DeliveryRunner 及并发容量；事务内领取，提交事务后调用驱动，另一个小事务保存结果。投递及必要启动不持房间文件锁或数据库写事务跨 RPC。
- 若仍需业务 guard，键限定为 `(room_id, channel_id)`，逐一列明用途、持有时间和调用方；禁止把频道协调回退成房间级投递长锁。既有后台单实例选主与消息业务锁分别看待，不增加入库锁。
- 调度器维护目标 session 的在途归属，覆盖提交及必要启动处理。按持久化投递顺序选择目标队首；队首退避时同目标后项等待，其他频道／目标在可用容量内继续。同 session 的约束由调度和数据库状态表达，不新增 session 文件锁。
- 暂时前置故障保留原标识进入等待，持久化下次尝试时间及必要诊断；读取时只取到期队首。退避参数集中，使用现有配置方式；不以耗尽内部竞争重试次数写成 unknown。
- 驱动按输入提交阶段和具体错误类型区分暂时不可用、确定配置／绑定失败、可能已发送；不依赖 `method is None` 将所有异常写成 rejected，也不将 steer 回退后的异常误判为从未提交过。
- 已知成功回执先作为待保存结果处理，写库失败重试原结果，不再次调用 add/steer。真实不确定结果按原关联标识核验队列分页和输入历史；只有正向证据更新入队／接收事实。
- 当前没有上游幂等保证；保留已有 0.167.0 实验的版本边界，不对实际成员会话做新版实验，不批量恢复历史 unknown。

### Implementation protocol / 实施协议

- P01：请求事务是消息／路由／投递任务的唯一原子入库边界，既有正确路径不重写。后台领取必须在请求提交后，数据库写事务不包围任意外部 RPC。
- P02：同目标占用从领取开始，持续到完整 submit 作业返回，包含准备、add／steer、回执保存及必要 activation；写为 queued 不能提前放行同目标下一作业。无需等待模型整轮完成。调度器排除仍在执行的目标，仓储也保持提交状态条件约束；不新增 session 文件锁。
- P03：队首按持久化插入顺序选择，退避中的原队首不能被同目标后项跨过；不同目标／频道在容量内继续运行。输入历史观察不发送输入，确认更新不得将 received 回退为 queued／unknown。
- P04：提交和启动均移除房间业务长锁；只在确有必要时保留短的频道业务协调，说明具体用途。后台 singleton 选主锁保留，与业务锁区分。
- P05：明确未发送的暂时故障、确定配置／绑定失败、可能已发送三类分开；steer 已尝试后的回退不重置写入事实。持久化重试及恢复边界，不能只靠进程内冷却。新增字段必须迁移并核对打包。
- P06：已知回执保存失败只重试保存原结果；可能已发送则持续核验原队列／输入，不自动 add／steer。队列精确命中证明 queued，完整输入事实证明 received；未命中、缺页、不支持或超时均非未发送证据。有效旧队首为 `unknown` 且 `attempt_count > 0` 时阻挡同 session 后项，直到正向事实将其转为 queued／received；目标资格沿用 R01。迁移前历史 unknown 的 `attempt_count = 0` 不纳入新屏障，不自动补投或重写。没有正向事实的真实不确定项可能持续等待，这是外部证据边界，不伪造拒绝或接收。
- P07：高级开发负责代码、测试设计及失败分析；中级开发只运行明确命令并原样报告 exit code／结果，不分析设计、不修改产品或测试。format 如需写入，只对架构师／高级开发已列明的本轮文件执行，不并行改共享文件。
- P08：本轮新机制已保存原 queue 回执且未记录启动尝试的明确待检查任务，可持久化安排首次启动检查。observer 只保存队列正向事实和检查时间，不直接 start；runner 用 `claim_activation_work(excluded_sessions)` 领取，和 submit 共用 session 占用，核对 idle／精确原队首后调用一次性 claim_activation。未 idle／非原队首／只读准备暂时失败仅延后检查；记录启动尝试后无论成功、拒绝或未知均不重发 start。领取检查不能提前丢掉可恢复标记；标记清除与实际启动 claim 原子关联。历史 attempt_count=0、已有 activation_attempted_at 或没有明确待检查标记的旧 queued 不新增通用启动重试。另核对新任务已保存回执后、首次启动前崩溃的间隙，用相同明确标记恢复首次检查，避免依赖下一条新消息。
