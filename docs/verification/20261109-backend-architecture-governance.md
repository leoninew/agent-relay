## 计划对齐

沿用[总计划修订 3](../plan/20261109-backend-architecture-governance.md)：技术层优先、领域规则、中立契约、SQLite 适配、Codex 转换、短事务、按能力装配、运行机制与单次动作分离、独立 unit/integration 入口。事件由 `RoomChange` 表达，持久化代码同事务显式追加；基线 SQL 包含 10 张表、0 个触发器。

核对的事务路径：

| 路径 | 事务所有者与事件记录 |
| --- | --- |
| HTTP 写请求 | 中间件拥有惰性 `SQLiteTransaction`，provider 绑定请求存储；响应开始前提交，异常或错误响应回滚；用例不单独提交 |
| 发布和资源保存 | `write_rooms()` 提供业务操作，消息与固定投递、资源与 metadata 均使用当前写事务；对应事件由 store 追加 |
| 成员绑定和观察 | 先短读，退出作用域后调用外部能力，再短写重查；观察只有匹配条件的 UPDATE 才追加成员/会话事件 |
| 单次后台投递 | 领取、中断、完成、启动尝试、备注、接收确认分别拥有短 `write()`；外部 enqueue/start/read 在事务之外；`finish_delivery` 已采用 `write()` |
| 成员上下文 | 单次 `write()` 包含查询、提供记录和位置推进；只有位置 upsert 真正推进才产生 position 事件 |
| WebSocket | 使用进程查询能力，每轮补取独立短读；等待网络时不持有请求事务 |

本轮源码审查未发现本功能保留写入路径漏记事件；订阅关联改写合并为一个 member 事件，消息不可变，无独立消息更新路径。事件是变化通知，保留持久游标和断线补取语义，不要求每条关联表 SQL 生成一条事件。收尾独立新增的删除聊天室会整体删除该房间历史及事件，该新增行为不包含在本功能原有事件保留结论内。以上为源码结论，当前版本运行原子性未重新执行验证。
