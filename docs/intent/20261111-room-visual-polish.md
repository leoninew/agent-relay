# Intent / 意图：聊天室视觉与交互完善

最后修改时间: 2026-11-11 15:58:34

## Review status / 审查状态

Accepted

## Background / 背景

现有产品只有一个聊天室页面。已通过 jev-ultrafast-mcp 检查桌面页面、项目切换、筛选、详情、菜单、弹窗与表单校验，并补充 1024px / 390px 浏览器模拟。用户期望现代、明快、IT 工具风格，要求先记录 SpecFlow 任务再实施本轮审视提出的修正。

## Goals / 目标

- 改善输入焦点、触屏入口、手机消息区空间、错误提示可读性和大屏长消息行宽。
- 沿用白底、蓝色强调、紧凑工作台结构；正文 14px、右侧内容 12px 保持现有约定。

## Non-goals / 非目标

- 不增加页面，不重做三栏、分隔线、240px / 420px 初始恢复宽度或桌面详情行为。
- 不修改 API、数据库、发送与分发规则；不保存、创建或删除真实业务数据。
- 不引入字体下载、测试框架或其他依赖，不执行 Git 写入。

## User stories / scenarios / 用户故事 / 场景

- 键盘或鼠标进入表单后，能识别当前输入位置，错误状态仍然清晰。
- 触屏用户直接看到项目菜单入口；手机默认把空间留给消息和输入，通过按钮展开话题与成员。
- 大屏阅读较长的技术消息时，行宽适中；各视口仍可打开详情、选择筛选并输入。

## Acceptance criteria / 验收标准

- A01：普通输入、搜索与编辑区均有可见焦点反馈，错误输入保留错误色，禁用态不误显示为可编辑。
- A02：无悬停能力的触屏设备直接显示项目菜单按钮，点击可打开并取消菜单。
- A03：720px 及以下导航默认折叠，可展开 / 收起话题和成员；消息区与输入区在视口内分配空间，导航展开不会把输入推到页面之外。
- A04：浅色主题错误文字与白底对比度至少 4.5:1，错误提示和字段反馈继续有效。
- A05：大屏长消息有固定阅读宽度上限，窄屏不横向溢出；桌面三栏和初始恢复宽度保持。
- A06：弹窗标题与正文有适度层级，右侧内容保持 12px；项目已有类型、lint、格式及单元检查通过。

## Workload assessment / 工作量评估

主要交付是一组同页视觉与交互修正。修改集中在全局样式、聊天室样式、呈现组件和局部测试；颜色和焦点共用现有 token，手机导航复用 Reka Collapsible。工作量较小，复杂度中等，主要风险是手机可用高度和桌面面板回归。各项共享样式和布局边界，拆开协调成本高于收益。

结论：保持单任务，在同一计划记录实现和开发检查，不建立 task DAG。

## Candidate tasks and dependencies / 候选子任务与依赖

不适用。

## Open questions / 待定问题

暂无需要用户确认的未决事项。

## Decisions / 决策

- 以现有视觉体系增量完善，保留用户已确认的分隔线与右侧密度。
- 手机导航默认关闭，详情仍沿用已有抽屉；为导航展开内容设置高度上限。

## Risks / assumptions / 风险 / 假设

- 手机检查使用浏览器模拟，不等同于真实设备软键盘验收。
- 工作区存在其他前后端修改，按实际内容增量编辑，不回退共享修改。
