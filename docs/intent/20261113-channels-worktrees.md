## Background and goals / 背景与目标

项目目录当前只能对应一个聊天室，房间中的话题、成员及消息共同组织，多项任务并行时容易混杂。引入频道，使同一聊天室内的不同任务拥有独立协作空间和工作目录。

- 创建聊天室时使用用户选定的现有仓库工作目录，自动创建占据该目录的默认频道。
- 新建频道时提供“创建 Worktree”选项，默认不勾选；勾选后创建独立 Git worktree，未勾选时不创建 worktree。
- 频道各自拥有成员、话题、订阅、消息和协作上下文。同一聊天室内一个活动 Agent 会话只能加入一个频道，不同任务使用不同会话。
- 保持一个项目目录对应一个聊天室的现有使用方式；旧聊天室及其工作会话平滑进入默认频道。

## Non-goals / 非目标

- 不实现跨频道共享消息或成员订阅，不将频道称作权限或安全边界。
- 不自动合并分支、复制未提交或忽略的文件、安装依赖、移动现有会话或接管 Codex 会话创建。
- 首版不提供 worktree/分支删除、已有 worktree 接管、跨频道转发或目录残留管理平台。
- 实现授权覆盖频道前后端与隔离临时环境的必要检查；不据此操作现场数据库、现场 worktree、真实 Codex 投递、Git 提交或部署。

## Scenarios / 场景

- 用户创建聊天室，现有目录立刻归默认频道，已有对应目录的 Codex 会话可加入。
- 用户新增任务频道，直接点击“创建频道”；勾选 worktree 时自动从当前 commit 出发，并在新目录打开和添加会话，不另设用户预览步骤。
- 频道内发布、查询、清空及管理，只作用于该频道；同名话题或成员在其他频道互不影响。
- 旧数据库升级后，既有消息、会话绑定与待处理投递保留在默认频道，无重复投递。
- 频道包含名称和描述，详情只展示名称和描述；创建通过现有请求事务处理，不维护频道状态。
- Git 失败或目录占用时明确报错，回滚数据库写入，不覆盖或删除用户工作。

## Acceptance criteria / 验收标准

- A01：创建聊天室同时创建唯一默认频道并绑定原工作目录；选择 worktree 的频道使用独立工作目录，未选择时不创建 worktree。
- A02：新增频道时可选择 worktree，默认不勾选；点击“创建频道”一次提交，自动从当前 commit 出发。重复请求或响应丢失不会创建第二个 worktree，失败和中断可诊断且不破坏已有数据。
- A03：频道成员、话题、订阅、消息、引用、上下文、搜索、事件及队列互不串扰；每频道有固定用户“你”。
- A04：会话发现、绑定、能力发现及投递按频道工作目录执行；同一房间的活动 Agent 会话只能加入一个频道。
- A05：旧库迁移映射默认频道，保留消息 ID、序号、关联、发布幂等与投递状态及回执。所有频道调用显式指定频道，不提供旧入口或默认频道回退；缺失或错误的频道不能造成向其他频道发送或清理。
- A06：频道创建、切换及独立草稿、消息和成员操作可在 Web、HTTP、CLI、MCP 与协作 skill 中贯通。
- A07：频道或房间退出活动状态时阻止后续发布和新投递；处理与创建/投递并发的边界，保留事实与 worktree，不宣称撤回已送入会话的内容。中断及升级恢复不重发已接纳或未知投递。
- A08：覆盖迁移、隔离、并发与失败恢复的自动检查，并在隔离环境验证真实 Git、界面和投递链路；记录限制和结果。

## Risks / assumptions / 风险 / 假设

- worktree 隔离工作文件，但共享仓库对象及引用；同一会话上下文也不能被频道分割。
- Git 仓库、HEAD、路径、权限或机器重启可能导致创建失败；旧非 Git 目录仍允许作为默认频道，新增频道时明确报错。
- 既有接口、事件、消息 ID、投递回执和 SQLite 复合外键较多；旧服务不能与迁移后的新库混跑。
