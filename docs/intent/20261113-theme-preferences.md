## Goals / 目标

- 提供 `system | light | dark` 三种外观策略，建议初始默认值为 `system`；用户保存的选择按字段优先于配置默认值。
- 在浏览器和桌面网页内容中应用一致的主题机制；选择跟随系统时，运行期间也能响应系统外观变化。
- 复用当前界面的颜色、字号、间距与交互规则，补齐暗色适配，不另建视觉体系。
- 与语言共用用户偏好文件和接口，同时保留旧语言文件、语言单独更新及原有保存失败语义。
- 切换只更新外观，不刷新页面或重建聊天室组件，保留草稿、引用、路由和发布状态。

## Non-goals / 非目标

- 首期不增加独立设置页、自定义主题编辑器、第三套配色、定时切换、账号同步或多窗口实时广播。
- 不改变语言的系统判定规则，不将主题与语言绑定，不为主题引入数据库或数据库迁移。
- 首期覆盖网页内容；原生标题栏、Windows 确认框和进程启动错误框继续遵循其原有系统行为。应用固定暗色驱动原生窗口配色属于后续独立调查范围。
- 不以 CSS 切换承诺消除操作系统建窗至网页加载前的所有白屏，不以 Node 替身测试代替浏览器及 WebView 实测。
- 本次评估不实施产品代码，不提交或发布，不启动真实聊天室、桌面应用或后台服务制造验证数据。

## User stories / scenarios / 用户故事 / 场景

- 用户在齿轮左侧点击独立主题按钮，直接展开“跟随系统 / 明亮 / 暗色”，没有额外小标题；支持键盘及点击操作，勾选表示已确认的策略。齿轮菜单保留“语言”和“关于”，语言继续使用悬停子菜单。
- 用户选择暗色，保存确认后当前页面和已经打开的浮层随即变为暗色；下次启动仍采用暗色。成功使用现有 Toast，失败显示现有偏好错误反馈。
- 用户选择跟随系统，在系统外观变更时自动切换；选择明亮或暗色后，系统变化不覆盖固定选择。
- 用户原来仅有 `{"language":"en"}` 偏好文件，升级后语言保持英文，主题采用配置默认值；保存主题不会重置语言。
- 用户没有明确保存语言，只保存主题，之后修改配置默认语言仍可生效；保存 `system` 则代表明确覆盖配置值。
- 用户在发送中、草稿编辑中或结果待确认时切换主题，操作上下文及 publication ID 保持，不发生重发或额外订阅重建。
- 偏好接口失败或浏览器不提供系统主题能力时，页面仍可显示和重试，不产生虚假保存成功。

## Recommended approach / 建议方向

### Preference contract / 偏好契约

建议增加 typed config `preferences.theme`，允许 `system | light | dark`，默认 `system`；沿用当前集中配置校验和用户目录 `~/.agent-relay/preferences.json`。不增加启动参数。

GET 返回完整的语言偏好、`resolvedLanguage` 和主题策略 `theme`。主题的实际明暗由当前浏览器／WebView 解析，不由后端返回一个代表服务进程环境的 `resolvedTheme`。系统主题与显示语言是不同来源，不复用语言的启动快照。

当前 `UpdatePreferences` 同时承担写请求与文件校验，且 `PreferencesStore.load/save` 只传递语言字符串。需要将持久化模型与部分更新请求分开，使存储能表达各字段是否存在，服务按字段合并默认值。PATCH 支持仅传语言、仅传主题或同时传两者，拒绝空对象、未知字段、显式 null 和非法枚举；现有语言单字段请求继续有效。

保存时只改请求中的字段，保留其他用户覆盖及其缺省状态；不要把未明确选择的配置默认值固化成用户选择。读取旧文件不主动重写。沿用同目录临时文件及原子替换，锁覆盖同一服务实例中的整个读取、合并、写入过程，防止更新两个字段时丢失其中一个。跨进程同步不纳入首期。

前端沿用保存确认后应用的模式，以及超时／断连后 GET 核对的处理；按本次请求字段确认结果，不自动重试 PATCH。语言与主题保存共用进行中状态，避免同时操作造成覆盖，旧响应不能覆盖较新的状态。

### Theme application / 主题应用

建议将 `.dark` 统一施加到 `document.documentElement`，同步 `color-scheme`，使 Teleport 至 body 的菜单、Toast、Dialog 和原生表单控件都覆盖到。有效主题由策略和 `matchMedia("(prefers-color-scheme: dark)")` 计算，系统监听只装配一次并支持清理；能力不可用时 system 回退明亮，固定暗色仍然可用。

主题装配放在应用启动边界，不放在齿轮菜单或聊天室组件里，避免菜单每次开关重复注册监听，也避免主题切换改变路由、组件 key 或发布状态。已有颜色变量优先复用，成功／在线等确有独立语义的颜色再补充配对 token；保留话题之间的颜色区分。

首次绘制需要分层处理：先尽早根据系统设置根主题，再在偏好响应后应用已保存策略。若增加启动缓存，只缓存已确认的策略，校验失败或存储受限时可回退；API 和用户目录文件仍为权威来源。缓存缺失、配置改变或不同来源地址访问时，首次背景仍可能需要纠正。Plan 阶段确定是否加入这种缓存及初始化位置，并在真实 WebView 中检查收益，不承诺仅在 Vue 挂载前设 class 即可解决所有闪白。

### Interaction / 交互

在齿轮图标左侧增加独立主题按钮，两个按钮紧凑并排。按钮按已确认策略显示系统显示器／太阳／月亮图标，悬停提示与无障碍名称包含当前策略。点击主题按钮直接展开三项 radio，选项文字为“跟随系统 / 明亮 / 暗色”，英文为“System / Light / Dark”，每项使用相应图标；勾选及按钮图标跟随策略值，不因为系统当前为暗色就把“暗色”标成已选。齿轮菜单保留语言悬停子菜单与关于入口。

继续使用现有菜单宽度、caption 字号、hover 与焦点反馈；顶栏主题和齿轮按钮使用 20×20 px 图标、32×32 px 按钮区域。不增加当前生效说明、小标题或独立保存按钮。成功 Toast 与错误反馈参与中英切换。系统自动变更不弹保存成功 Toast，也不写回偏好文件。

## Acceptance criteria / 验收标准

- A01：配置支持三种合法主题策略、默认 system，非法配置集中报错；已保存主题优先于配置，未保存字段继续继承配置。
- A02：旧语言文件与旧语言 PATCH 请求继续可用；分别保存语言、主题不会重置另一字段，未显式覆盖的默认值不被固化；空请求、null、未知字段及非法枚举被拒绝。
- A03：齿轮左侧提供独立主题按钮，直接打开无小标题的三项单选菜单，准确表示已确认策略，支持键盘及点击；中英文字与保存反馈完整。齿轮菜单保留语言与关于，语言支持悬停展开。
- A04：system 在启动及运行中按当前客户端主题解析；固定 light／dark 不受系统变化影响；无系统检测能力时有明亮回退；监听不重复并可清理。
- A05：根主题与 `color-scheme` 一致，主界面、空状态、菜单、Tooltip、Toast、关于及业务 Dialog、输入、Markdown、标签、引用与各状态可读；必要文字对比度按 WCAG AA 核对，状态不只依赖颜色区分。
- A06：保存成功后生效并在重启后保留；明确失败保持原已确认状态，结果未知沿用 GET 核对，不重复写入或显示虚假成功；读取不主动覆盖损坏文件。
- A07：切换不刷新页面、改变路由或重建聊天室，不丢草稿／引用，不改变 publication ID、不自动重发，不触发业务 API 或订阅的额外重建。
- A08：记录首次绘制、900×600 桌面与窄浏览器、系统动态变化及源码／制品的实际检查结果；未实测项明确保留，不用构建和替身测试代替运行证据。

## Workload assessment / 工作量评估

可行性高，工作量中等，复杂度中等；没有新增运行依赖或数据库工作的必要。界面入口和两套基础变量已经具备，主要投入在将单字段偏好升级为可兼容的多字段偏好，其次是主题启动／监听和有限的固定颜色适配。桌面首次绘制及实际对比度存在中等验证风险。

主要影响范围：

- 后端：偏好 DTO、端口、文件存储、应用服务、HTTP 路由、启动装配和两个 YAML 默认配置，及相邻单元测试。
- 前端：偏好 API 类型与 Pinia store、应用启动、主题解析边界、`AppMenu.vue`、中英词条、`style.css`、`room.css` 和偏好告警；无需启用 `SettingsPage.vue`。
- 说明与审查：配置／覆盖优先级、文件升级兼容、菜单入口和原生窗口范围；审查时同时提供旧语言契约、新旧文件示例及完整主题切换前后状态证据。

建议保持单任务、单会话串行完成。后端字段语义、前端保存状态与菜单共享契约，分别派发会增加协调成本；当前没有足够独立的交付结果需要建立 task/DAG。后续 Plan 可按偏好兼容、主题装配与样式、开发检查的顺序展开，但本轮不登记实施安排。

必要检查复用现有工具：pytest 使用临时目录与 fake/mock 覆盖旧文件、逐字段覆盖、原子写失败及请求约束；Vitest Node 使用替身覆盖系统变化、固定主题、监听清理、保存核对和旧响应处理；运行相关类型、lint、格式和构建检查。真实布局、hover、对比度与 WebView 初始背景另行观察，不新增测试框架，不连接真实 SQLite、HTTP 服务、Codex 或聊天室。本轮未运行产品测试，因为仅形成评估文档。

## Risks / assumptions / 风险 / 假设

- 当前文件与请求采用严格字段校验。加入 theme 后，新版本必须兼容旧文件；旧版本可能拒绝含 theme 的新文件，不能声称双向兼容。回退需要备份并将偏好恢复为旧格式，保留语言；不为此增加数据库迁移。
- Web 与后端建议随同一版本交付；新版前端访问不支持 theme 的旧后端会被拒绝，应按失败反馈，不能静默当作保存成功。
- 系统主题以当前浏览器／WebView 的媒体查询结果为准，可能受客户端设置影响；它不等同于 Relay 服务进程机器的外观。
- 局部固定色可能在暗色下保留浅底或低对比度；灰阶、disabled、hover、选中状态和主题色前景需一起核对。
- 初期仍为本地单用户偏好模型，多客户端共享策略但各自解析 system；不新增主动推送，同步时机沿用启动和打开菜单读取。
- 当前语言功能仍有独立未完成交付与验收。本评估不表示这些工作已完成，也不授权覆盖其他会话的共享文件改动。
