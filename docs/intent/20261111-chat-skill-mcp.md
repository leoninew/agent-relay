# Intent / 意图：聊天室 Skill 与 MCP 引用

最后修改时间: 2026-11-12 08:16:13

## Background and goals / 背景与目标

- 用户要求在聊天室发送消息时支持 Skill 与 MCP，并澄清 Skill 使用 `$` 触发可用列表；`/` 不是 Skill 触发符。
- 当前 `RoomComposer` 只有正文、话题和成员路由；发布契约、消息存储和上下文没有能力引用。Codex 投递已经以 `skills/list` 定位并注入必需的 Relay Skill，但未接受用户选择；MCP 能力目录和消息引用亦未接入。
- 输入 `$` 可浏览、搜索并选择当前房间项目可用的 Skill；页面打开房间时预加载 Skill 目录，不阻塞消息加载。
- 按用户最新要求，`$` 只展示 Skill；聊天页面不查询或展示 MCP 候选。所选 Skill 随消息可靠持久化，最后由目标 Codex 会话使用。

## Non-goals / 非目标

- 不把 `/` 设为 Skill 触发符，不把 Skill/MCP 选择实现为独立页面或阻断正文输入的强制工作流。
- 首期不直接调用 MCP 工具、不收集 MCP 工具参数、不呈现工具执行结果；选择服务器不等同于工具被调用或执行成功。
- 不提供 MCP 安装、配置编辑、OAuth 登录、全局策略或凭据管理。
- 不改变聊天室成员/话题路由、消息可见范围、排队顺序、会话启动、回执核验及未知结果不自动重投规则。
- 不要求 CLI/MCP 客户端提供能力发现 UI；现有客户端不传能力引用时保持兼容。
- 不修改 README 填充产品介绍；只记录实现所需的 SpecFlow 意图、计划和 task。

## Scenarios / 场景

- 打开房间后 Skill 目录在后台加载；用户可直接输入 `$`、按名称过滤、用键盘选择 Skill，再继续编写消息。
- 选择话题或 @ 成员不会触发 MCP 查询；`$` 候选保持为房间项目的 Skill 列表。
- Skill 目录不可用、未授权、目标会话不兼容或目录过期时，用户能识别问题；正文编辑和普通消息不受目录查询故障阻塞。
- 同一发布编号用于结果找回时，消息正文、接收对象和能力引用保持一致；不能静默丢弃用户选择或重复提交未知结果。

## Acceptance criteria / 验收标准

- A01：仅输入 `$`（不包括 `/`）触发只含 Skill 的可访问候选弹层，不查询或展示 MCP；连续输入按当前光标处查询过滤，`↑/↓` 移动、`Enter`/`Tab` 选择、`Esc` 关闭。打开弹层时 Enter 不发送消息；IME 确认与 Shift+Enter 行为保持正确。选中项表现为可移除的类型化标签，查询片段不误留在正文，可在一条消息中多次选择。
- A02：进入房间时异步加载该房间项目目录的 Skill 列表；请求不重复绑定到消息翻页/筛选，不阻塞时间线及普通消息。列出名称、简述、来源和启用状态；搜索本地完成；显示加载中、空目录、部分失败、整体失败并提供刷新。
- A03：HTTP 能力目录只暴露前端所需的安全字段，不泄露本地绝对路径或任何凭据。Skill 以稳定、无歧义的 ID 区分同名项；MCP 目录按目标成员原会话查询，完整处理分页及逐服务器错误。
- A04：发布及响应、历史消息、接收方 context、草稿与未决发布恢复均保留类型化 Skill/MCP 服务器引用。持久化迁移、领域/接口契约、上下文映射和 publication replay 校验全部包含引用；未携带引用的旧消息/旧客户端行为不变。
- A05：队列 adapter 把所选 Skill 解析为 Codex 原生 `skill` 输入，把 MCP 服务器解析为原生 `mention`（`mcp://<server>`）；和强制 Relay Skill 合并去重。拒绝或失效的引用在 `queue/add` 前形成确定的投递拒绝；RPC 提交结果不确定时继续使用既有 unknown/不重发规则。
- A06：投递时按实际路由接收人和目标会话核验引用；目录过期或调用时会话能力改变不能被静默忽略，单个目标的失败有明确投递事实且不影响其他目标。
- A07：记录实际运行的轻量目录/API 单测和源码检查；不新增或运行前端 UI、整页、跨层或真实 SQLite 测试，界面由用户验收。

## Workload and decomposition / 工作量与拆分

中偏大、跨前端、HTTP/application、持久化和 Codex 协议。主要不确定性是多会话的 MCP 可用性及消息引用的持久化/投递边界；Codex 当前协议已有目录与原生 Skill/MCP 引用，但调用结果仍须遵循 Relay 的可靠投递状态。按能力发现、消息契约与存储、前端 `$` 选择、原生投递四个可检查结果拆分；依赖与共享文件串行见总计划 DAG。

## Questions and decisions / 问题与决策

- 已确认：Skill 使用 `$` 触发列表；`/` 不用于 Skill。记录依据：用户消息 `room-94f73433cde7-msg-0098`。
- 实现决策：`$` 仅展示房间打开时预加载的 Skill；移除前端 MCP 查询、缓存、候选和相关提示，后端已有消息引用与投递契约继续兼容。
- MCP 首期绑定服务器引用与可用工具目录，不代表用户要求逐项直接调用函数；直接调用、参数表单和结果展示排除在首期之外。
- 通过消息能力引用选择（结构化标签），不依赖文本里易失的 `$name` 猜测执行意图；投递时按目标会话重新核验。
- 以上产品/协议决策已依据用户消息 `room-94f73433cde7-msg-0101` 接受并进入 Implementation；如用户要求直接执行特定 MCP 函数或不同的多收件行为，先回到 Intent 调整。

## Risks / assumptions / 风险 / 假设

- Codex 版本、`mcpServerStatus/list` 分页及 Skill 来源元数据可能变化；以当前 CLI schema 为基线并在 driver adapter 中验证，不让协议对象穿透 application。
- 目录是查询时快照而非执行保证；转发前重新解析，确定失败与 queue/add 后的结果未知严格区分。
- 当前前端草稿和 sessionStorage 保存完整发布请求；加入引用须更新重试路径，否则结果未知时可能把不同请求复用同一 publication ID。
- Schema 变更需正式 Alembic 迁移，不依赖启动自动建表；按用户约束使用离线 SQL 和单层单测核对，不运行真实 SQLite 或跨层测试。
- 当前工作区有其他未提交前端导航排序修改；执行者须增量修改，不能覆盖或回退。
