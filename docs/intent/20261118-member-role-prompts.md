# Intent / 意图：添加成员时发送角色提示词
最后修改时间: 2026-11-18 21:21:28

## 审查状态

Accepted。依据用户的功能描述、两项澄清和「记录和拆分任务」指令；后续实施授权见总计划。

## 背景与目标

- 通过聊天页右上角齿轮进入站点级「角色与提示词」设置页，在站点内复用角色模板。每个角色由名称和一段提示词组成。
- 添加成员时仍从现有可用 Codex 会话中选择；角色非必填，只能选一个。选中角色后，向新成员发送一条普通定向消息，正文为角色提示词。

## 非目标

- 不做分页、多角色、角色权限、模板变量、成员与角色的持久绑定或批量管理。
- 不修改系统提示词，不修改现有投递、重试和忙碌会话处理，不为提示词增加投递状态、送达提示或单独记录。
- 不新增服务运行参数的配置界面，也不改现有语言、外观和关于入口的行为。

## 场景与验收

| ID | 可检查结果 |
| --- | --- |
| A01 | SQLite 持久化站点级角色；可列出全量角色并新增、编辑、删除；升级保留现有成员与消息，重启后角色仍可读取。 |
| A02 | 齿轮菜单进入独立设置页，沿用现有按钮、表格和模态窗风格；列表无分页，支持新增、编辑与删除确认，并提供中英文。 |
| A03 | 仅添加成员时展示角色单选，可清空；不改变现有可用会话、成员名称和话题选择，不在编辑成员时发送提示词。 |
| A04 | 选中一个有效角色并添加成功时，当前频道新增一条普通消息；只定向给新成员，不携带话题。消息在聊天记录中可见，走既有消息与投递逻辑。 |
| A05 | 未选角色不产生消息；已删除角色、成员添加失败或消息持久化失败时不留下部分结果；重复绑定不额外发消息。角色编辑或删除不改写历史消息。 |
| A06 | 角色为空或读取失败时仍可按原流程不选角色添加成员；选中的角色被删除时能看到原因并重新选择或清空，无需重新填写其余字段。 |

## 工作量与拆分

工作量中等。角色配置与站点设置页是独立交付；添加成员跨成员和消息数据，重点验证原子保存和现有投递语义。拆成四项：角色持久化与 API（T01，A01）、设置页（T02，A02）、添加时的消息写入（T03，A04/A05）、添加成员表单（T04，A03/A06）。T02 与 T03 均消费 T01 的接口，可以并行；T04 消费设置页交付的角色 API 客户端和 T03 的成员提交契约。

## 问题与决策

- 用户明确角色不可多选；不选角色保留原行为。
- 用户明确提示词就是普通消息，继续走现有消息投递逻辑，不加提示词专属状态或送达反馈。普通定向消息归入当前频道聊天记录。
- 设置按当前站点共享；每次添加按角色的当前版本复制正文入消息，已有成员和历史消息不随模板变化。

## 风险与审查记录

- 成员与消息不能分成两个可独立成功的请求；需在同一数据库事务中写入，实际 Codex 投递留给现有后台流程。
