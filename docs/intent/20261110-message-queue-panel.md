# Intent / 意图：右侧消息队列面板
最后修改时间: 2026-11-10 22:25:33

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

右侧统一展示明确选中的消息、话题或成员；没有明确选择时直接展示当前列表最后消息，关闭详情清除选择并回到默认。消息队列作为各类详情的下级内容，展示相关的入队中或接收中消息，最新在上、最早在下。遵循现有三列布局、设计变量、组件和详情样式。

## Non-goals / 非目标

- 不改变发布、路由或操作实际 Codex 会话，不增加自动重发或任务完成状态。队列新增清空仅写业务记录的人为删除标记。
- 不重做导航、编辑表单或其他详情内容，不新增依赖；本轮仅按截图移除消息顶部摘要并统一话题/成员的标题操作组。

## Scenarios / 场景

- 打开或切换聊天室默认展示最新消息详情及全房间队列；话题详情附带该话题队列，成员详情附带其发送或接收消息的队列。队列范围随详情目标变化，不直接叠加聊天筛选或搜索。
- 同一消息有多个 Agent 接收人，仍有未删除的 pending/submitting/queued 投递时继续显示，全部接收、清空或仅剩失败/未知投递时移出。
- 较早的待接收消息不在当前聊天分页中，仍可从队列查看详情。
- 发布成功展示发送消息；普通实时新消息不抢占明确点选的消息、话题或成员。默认消息从当前结果派生，不另存默认对象；接收完成不强制清除明确选择。
- 小屏沿用详情抽屉，初始不覆盖聊天；关闭详情清除明确选择并显示当前列表最后消息，收起按钮关闭共同抽屉。
- 队列作为详情内的下级小节，空态紧凑，不再固定在右列底部。

## Acceptance criteria / 验收标准

- A01：进入和切换聊天室默认显示当前列表最后消息详情；点击消息/话题/成员建立明确选择，关闭详情清除该选择并回默认，空列表显示详情空态。各类详情均包含下级消息队列。
- A02：队列按消息去重，至少一个未删除投递为 pending/submitting/queued 才纳入；仅 received/rejected/unknown 或已删除投递不纳入。received 不代表任务完成，用户不计入 Agent 投递统计。
- A03：队列独立查询和分页，覆盖聊天页之外的积压；按消息 seq 降序展示，最新在顶，加载更多向下追加更早消息；当前详情范围内的消息总数准确，不使用投递数代替。
- A04：实时事件、重新加载及重连补取更新队列和所选消息；明确点选的消息只接受同 ID 更新，普通新消息不抢占选择。没有明确选择时从当前列表派生最后消息；发布成功仍展示发送消息。
- A05：沿用现有布局、字体和组件；队列作为详情下级内容，标题为“队列”且不展示数量。表格列为消息（正文前 15 个 Unicode 字符截断）、状态；右侧成员投递表为“名称/状态”，状态包含已接收、接收中、入队中。多接收人消息按未删除投递中最早未完成阶段汇总，不再展示 x/y 两列。小屏共同抽屉可打开和收起，初始不覆盖聊天，加载失败可重试。
- A06：相关后端查询、前端组件、请求及状态单测通过，既有类型、lint、格式检查通过。
- A07：话题与成员面板顶部分别固定“全部话题”和“全部成员”，打开或切换房间默认选中，不参与拖拽排序，点击后保持对应的全部筛选。
- A08：点击具体话题或成员是切换到该项，重复点击不取消；通过对应“全部”入口恢复该维度的完整范围，两个维度独立组合。侧栏操作仅在对应选项实际切换时触发消息筛选重载；重复点击当前项可打开详情，不重新加载消息、跳动滚动位置或重置输入区路由选择，重复点击已选中的全部项同样不重载。
- A09：通过全部入口使话题与成员同时未限定时清除明确详情选择，由当前结果派生最后消息；重复点击已选中的任一全部入口同样回默认，不重复请求或滚动。加载完成后派生结果自然更新，空结果不保留旧消息。
- A10：移除用户截图红框内的消息发送者、发送时间和正文摘要，消息详情从话题区开始展示，不保留摘要占位；话题、成员及分发状态仍使用现有展示。
- A11：话题和成员详情的编辑、删除按钮使用统一动作组，按钮之间及与标题的间距一致，文本基线对齐，不使用定位偏移。
- A12：消息详情的队列显示全房间活动消息；话题详情仅显示显式关联该话题的活动消息；成员详情仅显示该成员发送或作为已解析接收人的活动消息。切换详情重新建立该范围的分页及总数，不沿用上一范围的数据。
- A13：右侧各二级小节使用一致的标题、内容和无数据样式，包括成员订阅话题及队列；各二级小节不使用分隔线。
- A14：刷新右侧提供清空按钮，清除当前详情范围内全部未完成队列记录，包括未加载分页。仅对未完成 Agent 投递写人为删除标记及时间，保留原消息、已接收记录、状态、入队时间和回执；不调用 Codex 会话操作。被标记记录不再参与队列、待提交和接收核验；界面不显示“人为删除”文案。
- A15：消息详情删除独立的 @成员小节，原分发投递表作为“成员”小节保留；不重复展示同一批成员身份。
- A16：点击右侧队列消息展示详情；该消息已存在于主面板当前列表时，同时定位并滚入视口。当前列表没有该消息时不改变筛选或分页，仍可查看队列消息详情。

## Workload and decomposition / 工作量与拆分

中等规模，涉及只读队列查询、前端独立数据与面板状态，以及针对性检查。业务规则和已有状态明确，主要风险是聊天分页漏掉积压及实时更新抢占详情。由当前会话完成端到端实现和必要开发检查；不建立独立 task，避免小范围集成增加交接成本。
