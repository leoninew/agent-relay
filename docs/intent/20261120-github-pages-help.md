# Intent / 意图：Conflua 用户帮助站
最后修改时间: 2026-11-20 17:32:47

## 审查状态

Accepted

## 背景与目标

README 主要面向开发者。`docs/guide/` 既有 Windows 和 macOS 桌面指南，也有发布流程和 TSID 评估，不能整体作为用户手册发布。首版通过 GitHub Pages 提供一个稳定入口，让新用户无需查阅开发文档，就能从下载应用走到收到 Agent 的第一条回复。

## 非目标

首版不发布内部设计、任务和验证记录，不建设完整开发者门户，也不改变消息投递或会话行为。

## 用户场景与验收标准

- A01 应用使用：面向熟悉 Git 和 Codex 的用户，能组织聊天室与频道、配置成员、按成员或话题派工，并从首次回复继续到实现者向审查者交接。以发布包实际操作核对接收范围、投递和回复；平台安装仅作附录。
- A02 排障：在启动失败、Codex 未认证或 daemon 不可用、消息没有回复的对应步骤，用户能找到检查方法及恢复成功的标志。
- A03 公开边界：审查构建产物，仅含明确选取的用户内容；平台安装说明各有唯一维护来源，README 和帮助站不各写一份。
- A04 发布：PR 可验证构建，默认分支更新后可部署；在实际项目站上打开首页、直接访问并刷新文章、检查图片和站内链接，均不因 `/conflua/` 子路径失效。
- A05 入口与维护：README、Web 和桌面端指向同一站点；Web 新标签打开，Windows 和 macOS 桌面端使用系统浏览器，原聊天室保持可用。发布清单包含用户步骤变更时的文档核对项。

## 工作量与拆分依据

工作量中等：内容要核对发布包，部署涉及独立于现有桌面构建的工作流，产品入口还需跨平台验证。复杂度主要在三者共享的文章路径和站点地址；主要风险是误发布内部文件、指南与实际版本不符，以及桌面窗口被外链替换。建议在 Plan 阶段建立三个 task，分别审查用户步骤、发布产物和客户端行为。
