# Intent / 意图：单选成员模型展示与切换
最后修改时间: 2026-11-16 07:44:00

## Review status / 审查状态

Accepted

## Background and goals / 背景与目标

- 在消息输入框的“话题”和“成员”区域之后提供模型选择；当用户直接选择一个成员时，展示该成员会话的模型，并支持点击切换。
- 目标是被直接选中的唯一 Agent 成员及其绑定的 Codex 会话，不是左侧消息筛选目标，也不是隐式切换所有消息接收者。
- 当前消息可同时选择话题和多个成员，话题还可能增加接收成员。模型动作只影响直接单选的成员；其他通过话题接收消息的成员不受影响。
- 当前项目通过共享 daemon proxy 访问 Codex，不通过模拟终端操作模型。

## Non-goals / 非目标

- 不为多人选择或仅选择话题时批量展示、切换或统一模型；不限制原有消息路由的多选能力。
- 不打断正在运行的轮次、不自动发送消息、不清空队列、不回滚已发生操作。
- 不新增推理强度、提供商配置、凭据管理或模型安装界面；不影响其他成员会话。
- 用户已追加授权“拆分任务，推进实现”，覆盖方案、子任务实施与必要开发检查；UI 测试由用户自行负责，不提交 Git。

## Scenarios / 场景

- 消息框直接选中一个有效 Agent 成员时，在话题、成员区域后展示该会话当前模型和可选模型，选择后切换该会话。
- 未直接选择成员、直接选择多个成员或成员无有效会话时，不展示可执行的模型切换；不得将这些情况误判为单选目标。
- 可同时选择话题；无论最终消息接收者有多少，模型切换仅针对直接单选的成员，不变更话题带出的其他成员。
- 切换成员、房间或频道时，不将旧成员模型结果、加载状态或失败反馈错误显示为新成员的状态。
- 空闲、忙碌、会话不可达、模型列表为空、当前模型未知、切换拒绝或请求结果未知时，准确显示实际结果，不把默认模型或空回执当作确认的当前模型。
- 忙碌时的模型变更适用于后续轮次，不声称已改变当前运行轮次；当前轮次中的即时消息仍按原有语义处理。

## Acceptance criteria / 验收标准

- A01：消息输入框在话题和成员两块区域之后提供模型区域；只有直接选中且有效的单个 Agent 成员时允许展示和切换模型，其他成员与话题路由行为不变。
- A02：从所选成员绑定的会话及其提供商获取实际可选模型和当前模型，正确处理分页、空列表、未知值及会话不可用；不使用硬编码的模型列表或把默认模型当成该会话当前模型。
- A03：点击模型只对所选成员的原会话发起切换；后端在操作前核对频道、成员、会话身份、目录及模型可用性，不影响其他成员或正在运行的轮次。
- A04：明确区分已确认切换、明确拒绝与结果未知；不盲目重试，不伪造当前模型。切换后及时读取真实会话状态并反映于界面。
- A05：切换单选成员、话题、房间或频道时，页面状态及请求结果保持对应关系；不改变发送、投递、队列和成员筛选语义。
- A06：覆盖必要的后端业务、适配、HTTP 契约和前端状态开发检查；UI 测试由用户自行进行，明确记录真实会话模型切换是否实测。
- A07：模型和话题、成员在同一行布局，沿用分隔符及列表项外观；请求失败使用 Toast，不在模型区域显示错误或“仅应用于…后续轮次”描述。
- A08：模型默认只展示目录前 4 项，超过 4 项显示“...”，悬浮展开额外浮窗展示完整可选列表；不显示刷新图标或“当前”字样，通过选中色表示实际模型，后四项外的选中状态通过“...”及浮窗体现。

- A09：成员与模型之间不保留成员 flex-grow 产生的空白，保留话题/成员同样的分隔符和列表项间距。
- A10：API 返回原始 `id`、`model`、`displayName`、`description`；页面按钮显示 `model`、tip 显示 `displayName`，选中/切换根据 `model`。
- A11：模型选中样式复用话题/成员的同一 CSS 背景规则，包括“...”所代表的选中项。

## Workload and decomposition / 工作量与拆分

中等工作量，涉及消息输入组件、会话能力查询、频道范围 HTTP 接口和 Codex 适配。按用户要求拆为 T01 会话模型接口（A02–A04、A10 接口字段）、T02 输入框模型选择（A01、A04–A05、A07–A11）、T03 集成与开发检查（A06）。依赖为 T01 → T02 → T03；主会话顺序执行，规避共享文件冲突。

## Questions and decisions / 问题与决策

- 用户已明确：约束为单选用户时支持模型展示与切换。按现有输入组件的成员复选语义，“单选”指消息框内恰好直接选中一个有效 Agent 成员；不将左侧成员筛选视为操作目标。
- 话题与成员是并列路由选项，话题可能使接收者超过一人。模型动作的目标仍只取直接单选成员，绝不隐式修改话题带出的成员。
- 当前轮次与后续轮次语义按现有 Codex 协议：`thread/settings/update` 的 `model` 适用于后续轮次；不承诺即时消息会改变当前运行轮次的模型。
- 尚无必须由用户决定的产品范围问题。提供商支持、当前模型读取与切换确认等协议细节属于计划阶段须验证的技术事项，不作为已实测承诺。

## Risks / assumptions / 风险 / 假设

- 2026-11-15：现有共享 daemon 实际 `model/list` 返回 14 个非隐藏模型，列表以实际提供商和账户为准，数量和名称不作为固定承诺。本机 0.169.0 schema 包含 `modelProvider` 筛选参数、`thread/read` 的 `model` 字段及 `thread/settings/update` 的模型字段。
- 使用随机不存在的会话验证 `thread/settings/update` 方法可达，返回 `thread not found`；没有修改真实会话，因此不能据此宣称已验证实际切换、读取回显、忙碌状态行为或推理强度兼容性。
- 点击后模型变更会影响该会话后续轮次，不仅限于本条消息；计划阶段需确定用户反馈、读取一致性与结果未知的安全处理。
- 仓库存在其他已暂存和未暂存改动。本记录不修改、不暂存也不恢复这些改动；实施前需重新核对实际工作区及成员打断功能的基线。
