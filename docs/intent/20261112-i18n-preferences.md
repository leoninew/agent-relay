## Background and goals / 背景与目标

Agent Relay 的 Web 与 Windows WebView 共用 Vue 页面，目前没有多语言基础设施。界面、公共组件、表单错误、API 业务错误与桌面原生提示包含中文；日期格式固定为 `zh-CN`。部分界面逻辑直接比较中文标签，需要与翻译工作一起改为语义状态判断。

本轮目标是交付简体中文与英文的 Web／桌面体验，并通过配置和应用菜单管理用户选择。用户原文要求（设置页随后按最新要求延期）：

> 配置中需要有语言的定义能力，不添加启动参数。默认跟随系统，判断是中文就用中文，否则用英文。你要添加一个偏好/设置页面，用来保存用户选择。

项目参考基线为 `3f8097acf376c565ed8ceef19306e14887a0413e`。记录任务时已有 `pyproject.toml`、`uv.lock` 暂存修改，本轮只新增过程文档，不覆盖或归属这些修改。

## Non-goals / 非目标

- 首期不支持第三种语言、繁体中文资源、在线翻译、翻译管理平台或语言包下载。
- 不增加语言启动参数；不改造 CLI 帮助及 Click 自带提示的整套多语言机制，MCP 描述继续使用英文。
- 不翻译聊天正文、用户与会话名称、默认话题等业务数据、路径及第三方描述；不因界面切换改写历史记录。
- 不为历史投递诊断新增数据库字段、回填或迁移。产品状态和摘要本地化，原始诊断允许保留原文。
- 不增加登录、多用户偏好隔离、远程客户端系统语言识别或多进程实时偏好推送；首期沿用本地单用户定位。
- 交接前仅记录意图、计划和 task；现已授权本独立会话实施。不提交 Git、不发布制品；整体 Verification 另行授权。

## Scenarios / 场景

- 未保存偏好且配置为默认 `system`：中文系统使用简体中文，其他系统使用英文；识别失败使用英文。
- 用户通过配置将默认语言设为 `zh-CN` 或 `en`，没有已保存用户选择时按配置运行。
- 用户在应用菜单选择固定语言：当前界面与桌面提示立即切换，重新打开后仍使用该选择。
- 用户保存“跟随系统”：保存策略值 `system`，后续启动重新判断，而不是把当时解析出的语言固定保存。
- 没有聊天室或聊天室加载失败时，用户仍可打开应用菜单、查看并修改语言。
- 用户带着草稿、路由目标、引用或结果待确认的发布打开菜单和切换语言，内容与发布身份保持，不触发发布或重发。
- 偏好保存失败时，显示当前语言的错误反馈，已生效语言与已保存内容保持原状态。
- 应用更换工作目录、升级或移动制品后，用户语言偏好仍从用户目录读取。

## Acceptance criteria / 验收标准

- A01：typed config 定义 `preferences.language`，允许 `system`、`zh-CN`、`en`，默认 `system`；无新增语言启动参数，无效配置启动时集中报错。
- A02：`system` 中文判定覆盖中文语言变体；非中文及识别失败均使用英文；持久化的是策略值。系统来源和重判时机以总计划为准，Web 与原生窗口一致。
- A03：应用菜单保存的用户选择优先于配置默认值；持久化位于用户目录，重启有效；缺省文件不阻止运行，写失败不形成虚假成功。
- A04：提供右上角应用菜单，包含三种语言选择及保存中／成功／失败反馈；不显示额外的当前生效语言说明，保存成功以 Toast 反馈并立即生效，无需重启；关于展示品牌和版本，独立设置页延期。
- A05：Web 公共组件、导航、表单、本地校验、空状态、状态标签、Tooltip、Toast、无障碍文本和日期支持中英；翻译不参与业务判断，切换不遗留存储在组件中的旧语言文案。
- A06：打开菜单和切换语言不丢草稿、引用及路由目标，不更换待确认发布的 publication ID，不自动重发；既有聊天室查询和订阅保持正确。
- A07：桌面启动失败摘要、日志路径标签、退出确认标题／正文及新发布的离线通知采用当前语言；取消关闭、通知目标、投递和关闭顺序保持既有行为，历史通知正文不改写。系统原生按钮遵循 Windows 自身语言。
- A08：HTTP 业务错误提供可翻译的稳定原因码，现有 HTTP 状态、错误结构、请求 ID、CLI/MCP 协议及投递状态语义保留；固定用户按身份显示“你 / You”，不修改数据库规范名和约束。
- A09：交付必要的替身单元／组件检查、词典一致性检查、既有开发检查和使用说明；记录英文布局、源码桌面与制品验证的实际执行情况，不将未运行项目标成通过。

## Questions and decisions / 问题与决策

- 用户已明确：首期中英、配置可定义语言、不增加启动参数、默认跟随系统、中文用中文而其他语言用英文、设置页保存选择。无阻止计划编制的需求疑问。

- 配置默认值与用户覆盖的具体字段、文件和 API 是总计划提出的技术方案，不冒充用户逐项确认的原文决策。
- 本地应用的“系统”在总计划中统一定义为 Relay 所在机器当前用户的显示语言；网页消费后端解析结果，不另以浏览器语言覆盖。远程用户各自系统语言不属于首期场景。

## Risks / assumptions / 风险 / 假设

- Windows 显示语言与区域格式不同，需使用显示语言来源；系统判定须可注入以支持替身检查。
- 新设置路由会影响 `RoomPage` 生命周期。只保留普通草稿不足以覆盖发送中和待确认发布，需保留完整页面状态并正确处理激活／停用。
- 固定用户“你”受 SQLite 约束且被 MCP 描述引用；只能按身份在展示层本地化，不能直接改名。
- 英文界面中业务数据及原始诊断仍可能为中文；这不属于词条遗漏，验收时须按来源核对。
- 真实 WebView2、系统语言及冻结制品行为需要实施后的实际环境验证；单元替身结果不能替代运行证据。
- 已核对 PyWebView 6.2.1 的 WinForms 确认框使用 `MessageBoxButtons.OKCancel`：本轮翻译应用提供的标题和正文，系统按钮标签由 Windows 提供，不新造原生对话框。
