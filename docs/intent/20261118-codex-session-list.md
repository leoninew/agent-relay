# 意图：在 Conflua CLI 查询 Codex 会话

最后修改时间: 2026-11-18 12:48:58

## 审查状态

Accepted（依据用户要求新增 `codex session list`，并在频道消息 #444 明确授权实现 `session get` 和 `queue list`）。

## 背景与场景

已有列表可发现本地会话。排查站点无法加入或消息等待时，还需要核对单个会话的目录与状态来源，以及 Codex 实际等待队列；后者与 Conflua 聊天室的投递积压不是同一个查询。

## 目标与验收

- A01：`conflua codex session list` 默认以常规文本列出当前目录的会话 ID、名称和状态，支持指定目录；所有 Codex 查询子命令均默认输出常规文本，仅 `-o json` 输出 JSON；列表文本及 JSON 均按 ID 倒序。
- A02：分别展示 daemon 状态与运行态。以当前 `CODEX_THREAD_ID` 或同目录存活 `resume UUID` 进程作为 `open` 证据；无法关联时运行态为 `unknown`，不推断会话已停止。
- A03：命令只读，不依赖 Conflua 服务，不启动或恢复会话；查询失败显式报错。
- A04：`conflua codex session get ID` 按完整 UUID 查看会话目录、名称、daemon 状态、运行态及证据来源，模型信息按可用情况展示；传入 `--cwd` 时精确核对目录。
- A05：`conflua codex queue list ID` 按完整 UUID 查询实际等待项，包含没有关联消息 ID 的条目，只显示元数据，不输出正文；空队列、协议不支持、查询失败可区分。

## 范围与工作量

复用仓库已有的目录发现驱动和 Housekeeper 的进程匹配规则。两个命令共享本机代理、CLI 输出与错误约定，改动量小，保持单任务；主要风险是旧版本队列协议不支持，以及进程证据不足。不会改动弹窗、加入条件或现有聊天室队列语义，不新增发送、恢复、删除、协作或历史正文读取能力。暂无需要用户确认的未决事项。
