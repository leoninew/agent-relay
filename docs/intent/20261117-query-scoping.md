# Intent：按交互范围查询数据
最后修改时间: 2026-11-17 16:14:54

## 审查状态

Accepted

## 背景与目标

目录筛选已减少新建成员时的 Codex 查询。2026-11-17 频道消息 0412 的审查还发现清空频道、MCP 投递、频道元数据、单成员操作和实时同步存在先读取大范围数据再筛选的问题。用户在 0413 要求使用 SpecFlow 记录后推进处理，并明确继续。

## 范围与场景

- 清空频道仅核验该频道绑定的会话；查询失败仍阻止清空，避免误删成员。
- 投递引用 MCP 时只查询选中的服务器；完整目录展示仍查询整个目录。
- 当前频道仅加载关联成员的会话，保留已删除成员关联以展示历史消息。
- 中断、模型、MCP 查询直接定位成员；状态观察只读取活跃绑定。
- 实时同步按当前话题、成员和关键词补取变更消息，保留已展示消息与详情需要的数据，并减少不涉及资源变化时的元数据读取。

## 非目标

不修改数据库结构或迁移，不恢复 path_key 或 Session.cwd，不改变频道归档、缓存、投递、可见性及历史展示语义。不优化低频的路径判重，不新增缓存体系。

## 验收标准

- A01：清空频道不调用全局会话发现；目录无会话时跳过 loaded 查询。
- A02：MCP 投递携带原生 serverName 条件并验证所选 ID；缺失或不可用仍正确报错。
- A03：频道快照只含当前频道成员关联会话；单成员查询和状态记录不读取完整 resources。
- A04：实时消息通过批量 SQL 筛选补取，现有消息、详情与引用仍可更新；仅活动变化不重复获取话题、成员、会话。
- A05：相关应用、Codex、查询及前端回归检查通过；不运行迁移测试。

## 工作量与拆分

中等工作量，涉及外部 RPC、SQL 范围和前端增量合并三个可独立审查结果，建立 T01、T02、T03。复杂度主要在保持清空失败语义、历史成员关联和实时详情更新；风险集中于实时同步遗漏。T03 依赖 T02 的查询契约。所有节点由架构师本会话串行实施并集成。

## 决策、风险与用户审查

- 依据本机 Codex schema 使用现有 cwd、serverName、thread/read，不假定不存在的批量 ID API。
- 保留共享工作区频道归档和缓存改动，前端事件同步区域已由高级开发在 0415 确认可修改。
- 暂无需要用户确认的未决事项。既有授权覆盖记录和实施及必要开发检查；整体验证阶段另按用户授权推进。
